# Setup & Usage

> 🇪🇸 [Versión en castellano](SETUP.es.md)

A shared brain for AI coding assistants. One set of rules, skills and agents that
**Claude Code, Codex, Gemini CLI, GitHub Copilot CLI and OpenCode** all read from the
same place, for every user account on the machine.

## What this is

| Directory | What lives there |
|---|---|
| `skills/` | Skills — invocable playbooks (`SKILLS_CATALOG.md` is generated) |
| `agents/` | Specialist subagents in Claude subagent format |
| `agents-lib/` | Extended agent library, categorized, with adapters for other assistants |
| `gstack/` | Orchestration tooling |
| `codex/` | Claude ↔ Codex handoff manuals |
| `scripts/` | Hooks and maintenance scripts |
| `vendor/` | Third-party skills, unmodified, each with its own LICENSE |
| `AGENTS.md` | **The rules.** Read by every assistant on every session |

**Knowledge only.** No execution state, no session logs, no credentials — see
[What never goes here](#what-never-goes-here).

## Requirements

- **Node.js 18+** — the hooks use only the standard library, no `npm install`
- **Bash** — for the maintenance scripts
- One or more of: Claude Code · Codex · Gemini CLI · Copilot CLI · OpenCode

## Install

### 1. Place the stack

Anywhere readable by every account that will use it. Outside any user's home is
recommended, so no single user owns it:

```bash
sudo git clone <repo-url> /opt/ai-stack       # or /srv/ai-stack, /usr/local/share/ai-stack…
export AISTACK_HOME=/opt/ai-stack             # add to your shell profile
```

The scripts resolve their own location, so `AISTACK_HOME` is **optional** — set it only
if you call them from somewhere unusual.

### 2. Multi-user access (optional)

```bash
sudo groupadd aistack
sudo usermod -aG aistack <user>                        # for each account
sudo chgrp -R aistack "$AISTACK_HOME"
sudo chmod -R g+rwX "$AISTACK_HOME"
sudo find "$AISTACK_HOME" -type d -exec chmod g+s {} + # new files inherit the group

# Recommended: new files get group write regardless of each user's umask
sudo setfacl -R -m g:aistack:rwX -m d:g:aistack:rwX "$AISTACK_HOME"
```

> Without the ACL, files created with a `022` umask land as `644` and other members
> can't edit them. With it, you never need a manual `chmod` again.

### 3. Wire your assistant

| Assistant | Command |
|---|---|
| **Claude Code** | `ln -s "$AISTACK_HOME/AGENTS.md" ~/.claude/CLAUDE.md`<br>`ln -s "$AISTACK_HOME/skills" ~/.claude/skills`<br>`ln -s "$AISTACK_HOME/agents" ~/.claude/agents` |
| **Codex** | `ln -s "$AISTACK_HOME/AGENTS.md" ~/.codex/AGENTS.md` |
| **Gemini CLI** | `ln -s "$AISTACK_HOME/AGENTS.md" ~/.gemini/GEMINI.md` |
| **Copilot CLI** | `ln -s "$AISTACK_HOME/AGENTS.md" <your-workspace>/AGENTS.md` |
| **OpenCode** | add `"instructions": ["<AISTACK_HOME>/AGENTS.md"]` to `~/.config/opencode/opencode.json` |

### 4. Optional: hooks

**Claude Code** — in `~/.claude/settings.json`:

```json
{
  "hooks": {
    "SessionStart": [{ "matcher": "startup|resume|clear|compact|fork",
      "hooks": [{ "type": "command", "command": "node <AISTACK_HOME>/scripts/hooks/memory-session-start.js", "timeout": 15 }] }],
    "Stop": [{ "hooks": [{ "type": "command",
      "command": "node <AISTACK_HOME>/scripts/hooks/anti-sycophancy.js", "timeout": 10 }] }]
  }
}
```

**OpenCode** — copy the plugin to every account:

```bash
sudo "$AISTACK_HOME/scripts/sync-opencode-plugin.sh"   # honours $AISTACK_USERS
```

**Codex / Gemini / Copilot** have no session hooks. Launch them through the wrapper so
they get the same context:

```bash
"$AISTACK_HOME/scripts/ai-start.sh" codex "review the diff before deploying"
"$AISTACK_HOME/scripts/ai-start.sh" gemini "analyse this schema"
```

## Usage

### Invoking a skill

```
/skill <name>          # Claude Code
```

Skills are auto-discovered from `skills/<name>/SKILL.md`, **one level deep only**.
Anything nested inside a collection folder is *not* discoverable — expose it with a
symlink if you want it invocable:

```bash
ln -s collection-name/skill-name "$AISTACK_HOME/skills/skill-name"
```

Other assistants read the same markdown as context; the `SKILL.md` files are portable
by design.

Browse what's available in `skills/SKILLS_CATALOG.md` and `agents/AGENTS_CATALOG.md`
(both generated by `scripts/gen-catalogs.sh` — never edit them by hand).

### The two protocols

Defined in `AGENTS.md`, invoked by name in conversation:

- **`@protocol-enforce`** — start of a task: read the project rules, its memory, pending
  handoffs, then run the tools check before proposing anything.
- **`@protocol-end`** — end of a task, **only after the user confirms it's done**:
  writes the session log, updates the memory bank, saves reusable knowledge, and records
  the close. See `/skill protocol-end`.

### Documentation debt

```bash
node "$AISTACK_HOME/scripts/hooks/doc-debt.js" check          # what's undocumented
node "$AISTACK_HOME/scripts/hooks/doc-debt.js" bootstrap      # baseline, install only
node "$AISTACK_HOME/scripts/hooks/doc-debt.js" record-close <project>
```

Compares each project's last-close mark against its file mtimes. Computed from disk
state, not from a session event — that's why all five assistants see the same debt.
The mark lives in `<project>/.agent-zero/last-close.json`. Disable with
`AISTACK_DOCDEBT=0`.

### Anti-sycophancy

`scripts/hooks/anti-sycophancy.js` flags praise, agreement without evidence and filler
sign-offs. On Claude Code the `Stop` hook **rejects the reply** and the model rewrites
it; on OpenCode the flattering opener is stripped; the other three only get the
instruction in their prompt. Run `--self-test` to check it. Disable with
`AISTACK_ANTISYC=0`.

## Optional tools

Two helper scripts wrap third-party tools whose dependencies are **not** versioned here
(they're install-time artifacts, hundreds of MB). Install them once if you want them:

| Script | Converts / does | Install |
|---|---|---|
| `scripts/markitdown-local` | PDF, DOCX, XLSX, PPTX → markdown | `python3 -m venv vendor/markitdown/.venv && vendor/markitdown/.venv/bin/pip install markitdown` |
| `scripts/graphify-local` | Local code graph of a repository | see the script header |

Both fail with a clear message telling you what to install, and `markitdown-local` falls
back to a system-wide `markitdown` if it finds one on the `PATH`.

## Environment variables

| Variable | Default | Purpose |
|---|---|---|
| `AISTACK_HOME` | auto-resolved from the script's own path | Stack root |
| `WORKSPACE_ROOT` | `$HOME/workspace` | Projects root |
| `AISTACK_USERS` | `user1 user2 user3 user4` | Accounts for the OpenCode sync |
| `AISTACK_ANTISYC` | `1` | `0` disables the anti-sycophancy check |
| `AISTACK_DOCDEBT` | `1` | `0` disables the documentation debt check |

## What never goes here

This tree is meant to be copied, shared and published. Keep out:

- **Credentials** — read them at runtime from your host's credentials store
- **Absolute paths and private IPs** — use the variables above
- **Execution state** — belongs in the project (`<project>/.agent-zero/`)
- **Session logs and narrative** — belong in `<project>/memorias/` (or your equivalent)
- **Logs, caches, temp files**

Rule of thumb: if it's reusable knowledge for *anyone*, it belongs here. If it describes
*what happened* in one session or project, it doesn't.

## Maintenance

```bash
bash "$AISTACK_HOME/scripts/gen-catalogs.sh"    # regenerate catalogs after adding skills
```

Before sharing or publishing, run the security gate:

```bash
grep -rnE "(PASS|PASSWORD|SECRET|TOKEN|API_KEY)\s*=\s*[\"'][^\"'\$<{]{6,}" . --exclude-dir=vendor
grep -rnE "192\.168\.|10\.[0-9]+\.|/home/[a-z]+/" . --exclude-dir=vendor
```

Both must come back empty.
